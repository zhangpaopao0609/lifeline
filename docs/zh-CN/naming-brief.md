## 一、背景：这是个什么产品

### 一句话

一个**远程控制本机 Cursor / CodeBuddy** 的工具（那两台是本地 IDE，AI 会话还在里面）。个人自用项目。

### 它是怎么跑起来的

- **本机**：一个 CLI（改名前叫 `agent-remote`，现在叫 `lifeline`）装上守护进程，通过 CDP 连上本机的 IDE（Cursor 用 `9222`、CodeBuddy 用 `9223`），读会话、执行命令。
- **远端**：一台 server 跑 socket.io 中继 + 静态页；本机 agent 主动**出站**连上去，本机不需要暴露到公网。
- **我**：手机浏览器打开网页，就接上了本机那个 IDE。

### 网页上我能做什么

- 实时看会话：我的消息、agent 的回复、工具调用、计划卡片
- **批准 / 拒绝** agent 的操作，跑 / 跳过命令
- 发新的 prompt
- 切 chat tab、切模式与模型
- 在多台机器之间切换（比如家里一台、公司一台）
- 需要我审批的时候，浏览器弹通知

### 两个我比较在意的设计

- **会话是连续的**：网页上看到的内容来自本机磁盘上的会话文件（实时投影），不是另起一个云端会话。同一个会话从桌面延续到手机，不会断。
- **一台机器可以并列两个 IDE**：Cursor 和 CodeBuddy 各占一个槽。

### 改名前：名字的起点（2026-09-16 前）

- 网页品牌位写着 `AGENT·REMOTE`，下面一句：「把你的 CodeBuddy / Cursor 装进口袋」
- 仓库、命令、配置目录都还叫 `agent-remote`

要换掉的是**产品名这一层**（网页上的名字、CLI 的名字、配置目录）；底下的协议标识不用动。

## 二、我为什么要做它（心路历程）

### 我最想表达的

> 我真的不想守在电脑旁，真的太浪费人的生命了。我完全可以出去，对不对？工作也一样能做。等我回来后，整个过程我还在现场，更能体现是我的样子。就好像生命延长。

- 守在电脑旁等它、等审批，是在浪费生命
- 我完全可以出去，工作照样在做
- 回来后我还在现场：整个过程我看得见，事情还是按我的方式来做的
- 那种感觉，就像生命被延长了

### 我的开发习惯

> 我个人的习惯是用 IDE 开发。

我不习惯把开发搬到浏览器里去。我的代码、我的环境、我要验证的东西，都在本机这个 IDE 里。

### 痛在哪

> 但现在 AI 开发可能会等很久，可能需要你审批之类的，你就必须一直守在电脑前面，不能走，对不对？

AI agent 干活要等，还时不时要审批。审批不来它就卡住——所以我被钉在电脑前，哪儿也去不了。

### 为什么不用纯远程开发

> 但如果完全用纯远程开发，又不是我的习惯。我看不到代码，也看不到整个过程，没办法直接验，改完了也没办法直接验，对吧？我觉得不是很习惯。

纯远程（云端 IDE、网页开发）能解决"人不在电脑前"，但代价是丢掉了本机的真实感：看不到代码，看不到整个过程，改完了也没法直接验证。

### 所以这个东西好在哪

> 这是我个人的习惯。但你又不能一直坐在电脑前，所以有这个东西就太好了。

它没有把我的开发搬到别的地方去，只是让我能从电脑前走开。

### 我自己对这个产品的理解

> 其实我们的产品本质上就是控制你的 IDE，对吧？能够远程操控你的 IDE。而且这样做的好处在于，会话是连续的，不会断，对吧？

- **本质**：控制我的 IDE——远程操控本机那个真实的 IDE。
- **好处**：会话连续、不会断。

## 三、起名标准：我最看重的两点

> 把 cursor 和 codebuddy 装进口袋。

> 我人走了，但会话还可以继续，并且整个现场就跟我坐在电脑上一样。我回来了，完全保持现场。

这两条要同时成立，缺一个都不算对：

1. **装进口袋**：两台 IDE（Cursor / CodeBuddy）都能带走，不需要把开发搬到别的地方去。
2. **现场不断**：走开时会话继续，整个现场和坐在电脑前一模一样；回来时现场一点没变。

一句话：**带走的是「我」，不是「现场」。**

## 五、定稿：Lifeline / 生命线（2026-09-16）

> 「请帮我给这个产品起一个新名字」到此结束——名字定了。

| 项 | 定稿 |
|---|---|
| 产品名 | Lifeline |
| 中文名 | 生命线 |
| CLI | `lifeline` |
| 配置目录 | `~/.lifeline` |
| 网页品牌 | `Lifeline` |
| 副标 | 把你的 CodeBuddy / Cursor 装进口袋 |
| 核心主张 | 线不断，人就自由。 |
| 主 slogan | 把守在电脑前的时间，还给你。 |
| 辅助 slogan | 人走，线不断；回来，现场还在。 |
| 另一句 | 带走的是你，不是现场。 |
| 通知 | `Lifeline · 需要你批准` |
| 多机切换 | `Lifeline · Home` / `Lifeline · Office` |

### 为什么名字不负责说「延长生命」

Lifeline 本身是「生命线」。它不直接说「延长」，但它说的是更根本的东西：

- 线不断，人就自由。
- 你敢走，是因为线还在。
- 你能走，是因为会话不断。
- 你回来还在现场，是因为这条线一直连着。

被省下来的等待、审批、守在电脑前的时间，就是你被延长的那部分生命。所以「延长生命」不是字面延长，而是：**把被等待和审批吃掉的时间，还给你。**

### 三层分工

不指望一个名字把两件事说完，各层各管一件事：

| 层 | 负责 |
|---|---|
| 名字 | 线不断 |
| 主张 / slogan | 延长生命、更自由 |
| 副标 | 装进口袋 |

## 六、定稿后的取舍

1. **英文 Lifeline 脏，中文「生命线」干净。** 英文里 Lifeline 被「保命 / 紧急」占得很重（美国 Lifeline 通讯补贴、大量紧急呼叫设备）；中文「生命线」的默认义偏向「命脉、离不开的东西」，保命味弱得多。所以让中文名当家、英文只当标识符。代价：将来若要面向英文语境，这个词的占用会跳出来。
2. **「生命线」是通用词，独占性一般。** 口头说「那个生命线」，别人可能先想到监控 / 运维工具。个人自用可接受。
3. **协议标识不动。** `AGENT_TOKEN` 等协议标识不在改名范围（见第一节「改名前：名字的起点」）。
